# Curriculum Management System - Architecture Overview

## System Design

### Entity Hierarchy

```
Curriculum (Root)
├── Unit (Child of Curriculum)
│   └── Lesson (Child of Unit)
│       └── Activity (Child of Lesson)
│           ├── TextActivity
│           ├── PdfActivity
│           ├── AudioActivity
│           ├── VideoActivity
│           ├── InteractiveActivity
│           ├── QuizActivity (has Questions with Answers)
│           ├── BookActivity (has BookPages)
│           └── HomeworkActivity (has HomeworkFiles)
```

### Entity Relationships

**One-to-Many Relationships:**
- Curriculum → Units
- Unit → Lessons
- Lesson → Activities
- QuizActivity → Questions
- Question → Answers
- BookActivity → BookPages
- HomeworkActivity → HomeworkFiles

**Many-to-One Relationships:**
- Unit → Curriculum
- Lesson → Unit
- Activity → Lesson

## Entities Created (18 total)

### Core Entities (6)
1. **Curriculum** - Top-level learning curriculum
   - Fields: name, description, icon, status, displayOrder
   - Relationships: has many Units

2. **Unit** - Learning unit within curriculum
   - Fields: name, description, audioName, icon, status, displayOrder
   - Relationships: belongs to Curriculum, has many Lessons

3. **Lesson** - Learning lesson within unit
   - Fields: name, description, audioName, icon, status, displayOrder
   - Relationships: belongs to Unit, has many Activities

4. **Activity** (Base class) - Learning activity within lesson
   - Fields: titleName, titleAudioName, description, icon, activityType, status, points, tag, topic, displayOrder
   - Relationships: belongs to Lesson
   - Inheritance: Single Table Inheritance for activity types

5. **Status** (Enum) - Status for all curriculum entities
   - Values: DRAFT, PUBLISHED, ARCHIVED

6. **ActivityType** (Enum) - Types of activities
   - Values: TEXT, PDF, AUDIO, VIDEO, INTERACTIVE, QUIZ, BOOK, HOMEWORK

### Activity Type Entities (8)

7. **TextActivity** - Text-based learning
   - Additional Fields: text, textAudio

8. **PdfActivity** - PDF document learning
   - Additional Fields: pdfUrl, audioOfPdf

9. **AudioActivity** - Audio learning
   - Additional Fields: audioWithMusic, audioWithoutMusic

10. **VideoActivity** - Video learning
    - Additional Fields: videoWithMusic, videoWithoutMusic

11. **InteractiveActivity** - External interactive content
    - Additional Fields: externalActivityUrl

12. **QuizActivity** - Assessment quiz
    - Additional Fields: percentageToPass, attemptNumber, numberOfQuestions
    - Relationships: has many Questions

13. **BookActivity** - Interactive book
    - Relationships: has many BookPages

14. **HomeworkActivity** - Homework assignment
    - Additional Fields: dueDate, instructions
    - Relationships: has many HomeworkFiles

### Supporting Entities (4)

15. **Question** - Quiz question
    - Fields: questionText, questionAudio, displayOrder, points
    - Relationships: belongs to QuizActivity, has many Answers

16. **Answer** - Quiz answer option
    - Fields: answerText, isCorrect
    - Relationships: belongs to Question

17. **BookPage** - Page in book activity
    - Fields: pageNumber, image, text, audioGeneratedByAi
    - Relationships: belongs to BookActivity

18. **HomeworkFile** - File attached to homework
    - Fields: fileName, fileUrl, fileType, fileSize, uploadedAt
    - Relationships: belongs to HomeworkActivity

## Database Schema

### Tables Created (Auto-generated by Hibernate)

1. **curriculums**
   - Primary Key: id
   - Columns: name, description, icon, status, display_order, created_at, updated_at

2. **units**
   - Primary Key: id
   - Foreign Key: curriculum_id → curriculums(id)
   - Columns: name, description, audio_name, icon, status, display_order, created_at, updated_at

3. **lessons**
   - Primary Key: id
   - Foreign Key: unit_id → units(id)
   - Columns: name, description, audio_name, icon, status, display_order, created_at, updated_at

4. **activities** (Single Table Inheritance)
   - Primary Key: id
   - Foreign Key: lesson_id → lessons(id)
   - Discriminator Column: DTYPE (activity type)
   - Columns: title_name, title_audio_name, description, icon, activity_type, status, points, tag, topic, display_order, created_at, updated_at
   - Type-specific columns: text, text_audio, pdf_url, audio_of_pdf, audio_with_music, audio_without_music, video_with_music, video_without_music, external_activity_url, percentage_to_pass, attempt_number, number_of_questions, due_date, instructions

5. **questions**
   - Primary Key: id
   - Foreign Key: quiz_id → activities(id)
   - Columns: question_text, question_audio, display_order, points

6. **answers**
   - Primary Key: id
   - Foreign Key: question_id → questions(id)
   - Columns: answer_text, is_correct

7. **book_pages**
   - Primary Key: id
   - Foreign Key: book_id → activities(id)
   - Columns: page_number, image, text, audio_generated_by_ai

8. **homework_files**
   - Primary Key: id
   - Foreign Key: homework_id → activities(id)
   - Columns: file_name, file_url, file_type, file_size, uploaded_at

## Design Patterns Used

1. **Single Table Inheritance** - For Activity types
   - All activity types stored in one table with discriminator column
   - Simplifies queries and improves performance

2. **Builder Pattern** - For entity and DTO construction
   - Lombok @Builder annotation
   - Fluent API for object creation

3. **Repository Pattern** - For data access
   - Spring Data JPA repositories
   - Custom query methods

4. **DTO Pattern** - For data transfer
   - Separation of persistence and presentation layers
   - Type-safe data transfer

5. **Service Layer Pattern** - For business logic
   - Transaction management
   - Entity to DTO conversion

## Best Practices Applied

1. **Separation of Concerns** - Entities, DTOs, Services, Controllers separated
2. **DRY Principle** - Base Activity class for common fields
3. **Single Responsibility** - Each entity has one clear purpose
4. **Open/Closed Principle** - Activity types extensible without modifying base
5. **Dependency Injection** - Spring's @Autowired for loose coupling
6. **Transaction Management** - @Transactional for data consistency
7. **Validation** - Jakarta Validation annotations
8. **Auditing** - JPA auditing for timestamps
9. **Ordering** - Display order for UI flexibility
10. **Status Management** - Draft/Published workflow

## Security Considerations

1. Role-based access:
   - SUPER_ADMIN, SCHOOL_ADMIN: Full curriculum management
   - TEACHER: View and assign curriculums
   - STUDENT: View assigned published curriculums only

2. Status-based visibility:
   - DRAFT: Only visible to admins
   - PUBLISHED: Visible to all authorized users
   - ARCHIVED: Hidden from students, visible to admins

3. Input validation:
   - All DTOs have validation constraints
   - Size limits on text fields
   - Required field validation

## Performance Considerations

1. **Lazy Loading** - ManyToOne relationships use FetchType.LAZY
2. **Batch Loading** - Repository methods return ordered collections
3. **Single Table Inheritance** - Reduces JOINs for activity queries
4. **Indexing** - Primary keys, foreign keys auto-indexed
5. **Caching** - Can be added with Spring Cache
